# Регламент выката production-сайта

Этот процесс относится к сайту «цветы.цветофор.рф» в `/var/www/cvety`.
Его исходная ветка — `redesign`; сервер разворачивает только конкретный
коммит из этой ветки.

## Порядок

1. Изменение разрабатывается и проверяется в отдельной ветке от `redesign`.
2. CI запускает тесты и сборку.
3. Проверенный код попадает в `redesign`.
4. В GitHub Actions вручную запускается «Выкат коммита redesign на production».
   Миграции включаются только для изменений, которым они действительно нужны.
5. Workflow собирает `public/build`, передаёт его во временную папку и
   вызывает ограниченный серверный скрипт.
6. Скрипт принимает только SHA, достижимый из `origin/redesign`, обновляет
   код, при необходимости зависимости и миграции, затем пересобирает кэш.
7. Workflow сверяет SHA на сервере и HTTP-ответ. Затем проверяется изменённый
   пользовательский сценарий вручную.

## Однократная подготовка сервера

С правами root установить `deploy/cvety-deploy` в
`/usr/local/sbin/cvety-deploy` с владельцем `root:root` и режимом `0750`.

Создать папку временных сборок и исключить её из серверного Git-статуса:

```bash
install -d -o codex-sub -g codex-sub -m 700 /var/www/cvety/.deploy/build
printf '.deploy/\n' >> /var/www/cvety/.git/info/exclude
```

В `/etc/sudoers.d/cvety-deploy` добавить ровно одно разрешение:

```
codex-sub ALL=(root) NOPASSWD: /usr/local/sbin/cvety-deploy *
```

Проверить файл командой `visudo -cf /etc/sudoers.d/cvety-deploy`. Скрипт
сам проверяет SHA и ветку, поэтому не принимает произвольные команды.

## Секреты Actions

В GitHub Settings → Secrets and variables → Actions добавить:

- `CVETY_DEPLOY_SSH_PRIVATE_KEY` — отдельный ключ только для Actions;
- `CVETY_DEPLOY_SSH_KNOWN_HOSTS` — host key VPS;
- `CVETY_DEPLOY_HOST` — IP VPS;
- `CVETY_DEPLOY_USER` — `codex-sub`.

Приватный ключ не хранится в репозитории, чате или на сайте. Существующий ключ
Codex не копируется в GitHub.

## Ограничения

Workflow не меняет `.env`, `storage/`, фотографии или базу данных без
явно выбранной миграции. Он не отключает проверку SSH host key и не выкатывает
код вне `redesign`. Откат — повторный запуск с SHA прежнего коммита; при
необратимых миграциях сначала восстанавливается резервная копия базы.
