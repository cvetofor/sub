## Рекомендуемый порядок работы

1. Сначала P0: платежи, время и подтверждение доставки. Эти пункты нельзя
   исправлять «частично» и выкатывать по отдельным файлам.
2. Затем P1, связанные с обещаниями и деньгами: отмена, возвраты и каналы
   связи. Перед текстовыми изменениями сверить их с утверждёнными правилами
   компании.
3. После этого P1 по качеству оформления: верификация телефона, адрес и
   единый день первой доставки.
4. Для каждого пункта: отдельная ветка → тесты → PR → `redesign` → ручной
   production-выкат по [регламенту](PRODUCTION_DEPLOY.md) → ручная проверка
   затронутого сценария.
5. После исправления строки из этой таблицы переносятся в раздел «Исправлено»:
   дата, ссылка на PR/коммит, что проверено и результат.

## Что проверить отдельно перед запуском рекламы

Эти пункты не являются доказанной ошибкой кода, но их нужно подтвердить
операционно:

- настроены ли и фактически выполняются cron-задачи Laravel каждую минуту;
- работает ли очередь задач для amoCRM и уведомлений;
- приходят ли SMS и HTTP-уведомления ЮKassa на production;
- есть ли резервная копия PostgreSQL до первой миграции;
- совпадают ли цены, планы, города и часы работы в админке с утверждёнными
  правилами компании.
